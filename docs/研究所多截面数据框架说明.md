# 研究所多截面数据框架说明

## 目标与边界

当前正式数据库的RI、RO、SI、SO只是 `M=4` 的一个实例。底层数据层按一般形式处理：

```text
一个工况文件 -> M个section -> 每个section包含自己的xi和N个outputs
```

M、N、section名称和output名称都不固定。数据层只描述“源数据有什么”，训练层再按
partition解析可用outputs与配置选择的targets。当前已接入1D/2D/3D训练；预测、结果
重组和AI模型仍未接入。

## 动态 section 发现

核心从实际header中的 `xi_<section>` 字段发现section，并使用完整后缀作为源名称：

```text
xi_A, xi_B, xi_C                 -> A, B, C
xi_ROTOR_INLET                   -> source section ROTOR_INLET
xi_MIXING                        -> MIXING（未知但合法的名称原样保留）
```

发现顺序只作为源顺序和人机展示信息，不参与数据归属、模型选择、保存或预测。其他字段
通过与已发现section的完整后缀匹配归组，不依赖列号，也不要求新增第五、第六个section
时增加专用函数。

## section alias

默认名称alias只做规范化：

```text
ROTOR_INLET  -> RI
ROTOR_OUTLET -> RO
STATOR_INLET -> SI
STATOR_OUTLET-> SO
```

RI/RO/SI/SO自身也做大小写规范化。未注册名称不被拒绝或改写；调用方可以传入扩展alias。
如果两个源名称归一到同一canonical section，则作为歧义明确拒绝。

## 动态 outputs

除每组的 `xi` 外，该section后缀下实际出现的所有变量均进入动态 `outputs`。核心中没有
component到targets的绑定，例如不存在 `CMP -> Vz/Rho` 或 `HPTB -> MA` 的条件分支。

不同section允许具有不同output集合，也允许具有不同xi数值和点数。Adapter不对齐xi、
不插值、不重采样、不统一径向网格。若某行某section没有xi且该组outputs也为空，只跳过
该section的该行，不影响其他section。

## variable alias 与物理处理边界

默认变量alias包括大小写规范化，例如 `Ma -> MA`，并可由调用方扩展。规范化后的名称和
源字段同时保留：

```text
outputs["MA"]
source_fields["MA"] = "Ma_SI"
```

alias只表示同一变量的不同写法。Adapter不执行 `Vz <-> MA`、单位换算、补造Rho或任何
物理推导；这类能力未来应由独立、显式的physical preprocessing模块承担。

## Canonical结构

工况级 `CanonicalMultiSectionData`：

```text
component, database, stage, station
speed_parameter, flow_parameter
speed_parameter_name, flow_parameter_name
schema, schema_name, schema_version
source_file, source_metadata_fields, source_metadata, units
sections: {section_name: CanonicalSectionData}
```

截面级 `CanonicalSectionData`：

```text
section, source_section
xi
outputs: {variable_name: values}
source_fields: {canonical_name: source_column}
units
```

当前路径中的 `CNC`、`CNF`、`RPM`、`W25COR`、`W4COR`、`W5COR` 等原始参数标识记录在
`speed_parameter_name` 和 `flow_parameter_name`。只记录来源名称，不改变参数值、物理
定义或单位。`units`默认为空；只有调用方明确提供时才保存。

## Schema与版本

- `institute_single_section / v1`：现有单截面正式数据。
- `institute_multi_section / v1`：动态M截面canonical Schema。
- `institute_four_section`：保留的当前正式四截面兼容标识；其canonical身份为
  `institute_multi_section / v1`。

兼容标识不会被删除，因此既有配置、测试和外部调用可继续使用Four-Section入口。

## 固定四截面名称的剩余位置

RI/RO/SI/SO固定列表只保留在以下非核心位置：

- `four_section_adapter.py`：验证名为Four-Section的兼容入口，并保持历史展示顺序；
- 当前正式数据库测试：表达当前样例的明确预期；
- 配置和文档：描述当前研究所数据实例。

`multi_section_adapter.py`和动态section发现服务不使用该列表限制解析能力。训练配置
支持 `targets: auto` 或显式target列表；target解析按径向partition独立执行，不存在
component到outputs的绑定。

## 模型准入

`institute_multi_section`与兼容的`institute_four_section`已准入当前1D/2D/3D训练加载器，
仅接收 `station=MAIN`。1D从每个源文件提取一条工况记录，partition仍为
`component + stage`，section不参与1D分区；2D/3D使用
`component + stage + section`。预测加载器仍不接收Multi-Section数据。
