# AIR2 Project1 程序使用手册

## 1. 程序定位

`AIR2 Project1` 是面向气动部件径向分布预测的离线建模与批量预测程序。程序以结构化径向分布数据为输入，完成工况参数解析、样本构造、模型训练、交叉验证、模型选择、模型保存和预测结果输出。

当前程序主要服务于两类工程场景：

1. 完整三维数据场景：已知 `rpm / wcor / xi`，预测 `mai / psi / tsi`。
2. 稀疏工作线场景：一个 `rpm` 只对应一个流量点，或预测阶段缺少真实 `wcor`，需要先补全流量再预测径向分布。

其中，`rpm` 表示转速工况，`wcor` 表示换算流量，`xi` 表示相对径向位置，`mai / psi / tsi` 为待预测的径向性能参数。

## 2. 项目目录

当前项目中，与程序运行和报告复现直接相关的目录如下。

| 路径 | 作用 |
|---|---|
| `config/benchmark_config.yaml` | 领域专用 1D、2D、3D 训练和预测配置 |
| `data/current/3d/CASE1` | 完整 3D 数据算例 |
| `data/current/3d/CASE2-1` | `CASE2` 稀疏数据下流量已知的 3D 建模与预测算例 |
| `data/current/3d/CASE2-2` | 方法二 `1D + 2D` 算例 |
| `data/current/3d/CASE2-3` | 方法三 `1D + 3D` 算例 |
| `workbase/current_scripts` | 当前数据场景使用的训练、预测和串联脚本 |
| `workbase/src/project1` | 程序包源码和统一命令入口 |
| `workbase/common` | 配置读取、校验、模型版本、输出写回等公共模块 |
| `docs` | 使用手册、测试报告和相关技术文档 |
| `tests` | 自动化测试用例 |

报告复现时，通常只需要修改 `config/benchmark_config.yaml`，然后通过统一命令或 `workbase/current_scripts` 下的脚本运行。

## 3. 数据案例

当前技术报告使用四个核心算例。

| 数据案例 | 数据特点 | 主要用途 | 最终预测形式 |
|---|---|---|---|
| `CASE1` | 一个 `rpm` 对应多个 `wcor` 流量点，径向样本较完整 | 验证完整数据库条件下的 3D 建模能力 | `(rpm, wcor, xi) -> mai / psi / tsi` |
| `CASE2-1` | 人为构造的稀疏数据，一个 `rpm` 对应一个 `wcor` | 验证流量已知时，稀疏数据下的 3D 建模与直接预测链路 | `(rpm, wcor, xi) -> mai / psi / tsi` |
| `CASE2-2` | 与 `CASE2-1` 使用同一组稀疏训练数据 | 验证方法二，即先补流量，再用 2D 模型预测 | `rpm -> wcor`，`(rpm, xi) -> mai / psi / tsi` |
| `CASE2-3` | 使用同一组稀疏预测输入，预测阶段缺少真实 `wcor` | 验证方法三，即先补流量，再调用 `CASE2-1` 的 3D 模型 | `rpm -> wcor`，`(rpm, wcor, xi) -> mai / psi / tsi` |

需要特别说明的是，`CASE2-1 / CASE2-2 / CASE2-3` 属于同一组 `CASE2` 稀疏场景。方法三 `CASE2-3` 复用的 3D 模型应来自 `CASE2-1/output`，而不是来自 `CASE1/output`。`CASE1` 是完整数据库建模基准，主要用于说明完整数据条件下的建模能力。

## 4. 输入数据规范

### 4.1 目录结构

领域专用数据通常按部件、级数、转速和流量组织。典型路径如下。

```text
DATABASE_CMP/STAGE_1/RPM_0.6/0.00681.txt
DATABASE_HTB/STAGE_1/0.555/0.01509.txt
```

程序从路径中解析工况元数据。

| 字段 | 来源示例 | 说明 |
|---|---|---|
| `component` | `DATABASE_CMP`、`DATABASE_HTB` | 部件或数据库类别 |
| `stage` | `STAGE_1` | 级数 |
| `rpm` | `RPM_0.6`、`0.555` | 转速工况 |
| `wcor` | `0.00681.txt`、`0.01509.txt` | 换算流量 |

其中，`CMP` 对应模拟 `STAGE 35`，`HTB` 对应模拟 `KG66`。`CMP` 数据当前尚未完全统一无量纲化，因此解释 `psi` 误差时，应优先结合相对误差。

### 4.2 文件格式

训练文件内部通常包含径向位置和目标量。

```text
xi psi tsi mai
0.000000 ...
0.020408 ...
```

预测文件应至少包含模型所需输入列。不同流程的输入要求如下。

| 流程 | 预测输入列 | 说明 |
|---|---|---|
| 直接 3D 预测 | `rpm, wcor, xi` | `rpm` 和 `wcor` 可来自路径或列，`xi` 通常来自文件列 |
| 1D 补流量 | `rpm` | 可来自路径或文件列 |
| 2D 预测 | `rpm, xi` | 用于方法二最终径向预测 |
| 3D 串联预测 | `rpm, wcor, xi` | `wcor` 由 1D 中间结果提供 |

目标量中的 `-999.0` 视为缺失值，不参与对应目标的训练。`xi` 是径向坐标，不应作为缺失目标处理。

## 5. 配置文件

领域专用流程统一读取：

```text
config/benchmark_config.yaml
```

该文件主要包含以下配置段。

| 配置段 | 作用 | 当前典型用途 |
|---|---|---|
| `dataset_schema` | 定义输入、输出、元数据字段、别名、缺失值和分区键 | 统一解释 `rpm / wcor / xi / mai / psi / tsi` |
| `benchmark_3d` | 3D benchmark 训练与交叉验证 | `CASE1` 或 `CASE2-1` |
| `benchmark_2d` | 2D benchmark 训练与交叉验证 | `CASE2-2` 方法二 |
| `benchmark_1d` | 1D benchmark 训练与交叉验证 | `rpm -> wcor` |
| `predict_1d` | 1D 批量预测 | 为 `CASE2-2` 或 `CASE2-3` 补全 `wcor` |
| `predict_2d` | 2D 批量预测 | 方法二最终径向预测 |
| `predict_3d` | 3D 批量预测 | `CASE2-1` 直接预测或 `CASE2-3` 方法三最终预测 |
| `models` | 当前运行时注册的模型名称说明 | 用于记录可用模型集合 |
| `advanced` | 随机种子、并行数、日志目录 | 控制运行环境 |
| `output` | 模型、排行榜和报告输出开关 | 控制结果保存 |

正式复现某个算例前，需要先确认对应配置段中的 `paths.input`、`paths.output` 和 `paths.model_output` 是否指向当前算例。

## 6. 关键脚本与命令入口

### 6.1 统一命令入口

当前推荐通过统一命令入口运行领域专用流程。

```powershell
python -m project1 current <command>
```

常用命令如下。

| 命令 | 底层脚本 | 作用 |
|---|---|---|
| `python -m project1 current benchmark-1d` | `workbase/current_scripts/benchmark_1d.py` | 训练并评估 `rpm -> wcor` 的 1D 模型 |
| `python -m project1 current predict-1d` | `workbase/current_scripts/predict_1d.py` | 使用 1D 模型补全 `wcor` |
| `python -m project1 current benchmark-2d` | `workbase/current_scripts/benchmark_2d.py` | 训练并评估 `(rpm, xi) -> outputs` 的 2D 模型 |
| `python -m project1 current predict-2d` | `workbase/current_scripts/predict_2d.py` | 使用 2D 模型生成径向性能预测 |
| `python -m project1 current benchmark-3d` | `workbase/current_scripts/benchmark_3d.py` | 训练并评估 `(rpm, wcor, xi) -> outputs` 的 3D 模型 |
| `python -m project1 current predict-3d` | `workbase/current_scripts/predict_3d.py` | 使用 3D 模型生成径向性能预测 |

统一入口的优势是命令稳定、便于文档复现；底层脚本的优势是便于开发人员调试单个流程。

### 6.2 串联脚本

方法二可以使用一键串联脚本：

```powershell
python workbase/current_scripts/workline_pipeline.py
```

该脚本的实际文件名为 `workline_pipeline.py`，完整路径为 `workbase/current_scripts/workline_pipeline.py`。它目前作为直接脚本入口使用，不是 `python -m project1 current <command>` 下的公开子命令。

该脚本用于串联 `CASE2-2` 的 `1D + 2D` 流程，默认执行完整流程，主要包括：

1. 运行 `benchmark_1d.py`，训练 `rpm -> wcor` 模型。
2. 运行 `benchmark_2d.py`，训练 `(rpm, xi) -> mai / psi / tsi` 模型。
3. 运行 `predict_1d.py`，生成 1D 中间结果。
4. 运行 `predict_2d.py`，生成 2D 预测结果。
5. 合并 1D 中间结果和 2D 预测结果。

脚本支持通过 `--mode` 控制执行范围：

| 命令 | 作用 |
|---|---|
| `python workbase/current_scripts/workline_pipeline.py` | 默认等同于 `--mode all`，依次执行训练、预测和合并 |
| `python workbase/current_scripts/workline_pipeline.py --mode train` | 只执行 1D 与 2D benchmark 训练 |
| `python workbase/current_scripts/workline_pipeline.py --mode predict` | 只执行 1D、2D 预测和结果合并 |

方法三当前建议按步骤运行 `predict-1d` 和 `predict-3d`，这样可以明确检查 `results_1d` 中的 `wcor` 是否已经正确生成。

### 6.3 支撑模块

除入口脚本外，程序还包含若干公共模块。

| 模块 | 作用 |
|---|---|
| `workbase/common/config_loader.py` | 读取 `benchmark_config.yaml` 并提供各流程配置 |
| `workbase/common/validators.py` | 检查目录、文件、列名和数值有效性 |
| `workbase/common/model_factory.py` | 根据模型名称构造回归模型 |
| `workbase/common/model_versioning.py` | 保存模型元数据、模型清单和版本信息 |
| `workbase/common/prediction_output.py` | 按模板格式写回预测结果 |
| `project1/services/meta_parser.py` | 从路径中解析 `component / stage / rpm / wcor` |
| `project1/experiments/benchmark_runners.py` | 2D、3D benchmark 的核心执行逻辑 |
| `project1/experiments/benchmark_1d_runner.py` | 1D benchmark 的核心执行逻辑 |

这些模块通常不需要直接运行，但它们决定了数据读取、模型训练和结果输出的行为。

## 7. 建模与预测流程

### 7.1 1D 建模

1D 建模用于单输入关系拟合。当前 `CASE2` 中主要学习：

```text
rpm -> wcor
```

该模型用于在预测阶段缺少真实 `wcor` 时，先补充流量信息。当前配置对应：

```yaml
benchmark_1d:
  paths:
    input: "./data/current/3d/CASE2-2/train"
    output: "./data/current/3d/CASE2-2/output_1d"
```

运行命令：

```powershell
python -m project1 current benchmark-1d
```

### 7.2 2D 建模

2D 建模用于方法二，输入为：

```text
rpm, xi
```

输出为：

```text
mai, psi, tsi
```

方法二的基本链路为：

```text
1D: rpm -> wcor
2D: rpm, xi -> mai / psi / tsi
```

运行命令：

```powershell
python -m project1 current benchmark-2d
python -m project1 current predict-1d
python -m project1 current predict-2d
```

也可以使用串联脚本：

```powershell
python workbase/current_scripts/workline_pipeline.py
```

需要注意的是，2D 模型依赖分区内样本量。当前 `CASE2-2` 中，`HTB:S1` 可形成可用 2D 模型，`CMP:S1` 在稀疏配置下未形成稳定可用的 2D 分区结果。

### 7.3 3D 建模

3D 建模用于完整径向分布预测，输入为：

```text
rpm, wcor, xi
```

输出为：

```text
mai, psi, tsi
```

运行命令：

```powershell
python -m project1 current benchmark-3d
```

当用于 `CASE1` 时，配置应指向：

```yaml
benchmark_3d:
  paths:
    input: "./data/current/3d/CASE1/train"
    output: "./data/current/3d/CASE1/output"
```

当用于 `CASE2-1` 时，配置应指向：

```yaml
benchmark_3d:
  paths:
    input: "./data/current/3d/CASE2-1/train"
    output: "./data/current/3d/CASE2-1/output"
```

### 7.4 方法三预测

方法三用于预测阶段缺少真实 `wcor`、但希望保留三输入模型形式的场景。基本链路为：

```text
1D: rpm -> wcor
3D: rpm, wcor, xi -> mai / psi / tsi
```

在当前 `CASE2` 组内，方法三的 3D 模型应复用 `CASE2-1/output`：

```yaml
predict_3d:
  paths:
    input: "./data/current/3d/CASE2-3/results_1d"
    model_output: "./data/current/3d/CASE2-1/output"
    output: "./data/current/3d/CASE2-3/results_3d"
```

运行命令：

```powershell
python -m project1 current predict-1d
python -m project1 current predict-3d
```

第一步生成 `results_1d`，第二步读取 `results_1d` 中的 `rpm / wcor / xi` 并生成最终 3D 预测结果。

## 9. 输出文件说明

程序训练和预测后会生成以下类型结果。

| 输出类型 | 说明 |
|---|---|
| `leaderboard*.json` | 各模型在不同目标、分区和验证方式下的误差指标 |
| `benchmark_report*.md` | Markdown 格式 benchmark 报告 |
| `models/` 或 `models_2d/` | 保存训练后的模型文件；1D流量模型按`部件_级号`建立子目录 |
| `models_manifest.json` | 训练模型清单 |
| `model_metadata*.json` | 模型版本、训练字段和依赖信息 |
| `run_config_latest.yaml` | 本次运行使用的配置快照 |
| `results_1d/` | 1D 预测中间结果，通常包含预测得到的 `wcor` |
| `results_2d/` | 方法二的 2D 预测结果 |
| `results_2d_merged/` | 方法二中 1D 与 2D 的合并结果 |
| `results_3d/` | 方法三或直接 3D 预测的最终结果 |

报告中常用评价指标包括：

| 指标 | 含义 |
|---|---|
| `MAE` | 平均绝对误差 |
| `RMSE` | 均方根误差，对较大误差更敏感 |
| `MAPE` | 平均相对误差，报告中建议写成百分比 |
| `R2` | 拟合优度，用于衡量模型解释能力 |

## 10. 模型名称对照表

程序输出文件和排行榜中使用英文模型名。技术报告中建议同时给出中文名称、方法类别和必要的机理说明，便于把程序输出结果与代理模型理论介绍对应起来。

按照技术报告中的写法，本项目模型可归入三大类：

1. 通用回归模型：预先给定函数族或基函数形式，再通过最小化误差求解参数。
2. 非参数与高性能非线性模型：不强调显式全局解析式，而通过邻域、核函数、概率先验或树结构逼近未知映射。
3. 融合工程先验的领域特定模型：在统计模型基础上引入工作线、径向端点或物理约束等工程知识。

| 程序模型名称 | 报告中建议名称 | 对应报告方法 | 类别 | 说明 |
|---|---|---|---|---|
| `linear_deg2` | 二次多项式回归 | 多项式回归方法 PR | 通用回归模型 | 先构造二次多项式特征，再进行线性回归 |
| `ridge_deg2` | 二次多项式岭回归 | 正则化回归方法 RR | 通用回归模型 | 二次多项式特征叠加 L2 正则化 |
| `poly2` | 二次多项式岭回归 | 多项式回归 / 岭回归 | 通用回归模型 | 1D 工作流中的二次多项式基线模型 |
| `poly3` | 三次多项式岭回归 | 多项式回归 / 岭回归 | 通用回归模型 | 1D 工作流中的三次多项式模型 |
| `lasso` | Lasso 回归 | 正则化回归方法 Lasso | 通用回归模型 | 通过 L1 正则化压缩冗余特征 |
| `elastic_net` | 弹性网络回归 | 正则化回归方法 ENR | 通用回归模型 | 同时引入 L1 与 L2 正则化 |
| `piecewise_ridge` | 分段岭回归 | 分段回归方法 | 通用回归模型 | 按输入空间分段，并在各段内使用岭回归 |
| `spline_regression` | 样条回归 | 样条回归方法 SR | 通用回归模型 | 采用样条基函数描述平滑变化 |
| `tensor_spline` | 张量样条回归 | 多维样条回归方法 | 通用回归模型 | 通过张量化样条描述多输入耦合关系 |

## 11. 使用注意事项

1. 运行前应先检查 `config/benchmark_config.yaml` 中对应流程的输入、模型和输出目录，避免把 `CASE1` 与 `CASE2` 的模型目录混用。
2. 当前 `CASE1` 和 `CASE2-1` 的 3D benchmark 均使用 `n_splits = 3`。如果正式报告必须声明五折交叉验证，需要修改配置并重跑。
3. `CMP` 数据尚未完全统一无量纲化，解释 `psi` 误差时应优先结合相对误差。
4. 方法二依赖 2D 分区样本量；当分区样本不足时，可能无法形成可用 2D 模型。
5. 方法三在 `CASE2` 组内应复用 `CASE2-1/output` 的 3D 模型，其最终精度仍会受到 1D 补流量误差影响。
6. 方法三预测文件建议显式包含 `rpm xi` 列。若原始预测文件名使用数值型流量名，应确认 1D 中间结果中的 `wcor` 不会被路径解析覆盖。
7. 每次训练完成后，应保留 `run_config_latest.yaml` 和 `models_manifest.json`，便于追溯模型来源和配置。

## 12. 小结

当前程序已经形成以 `CASE1 / CASE2-1 / CASE2-2 / CASE2-3` 为核心的建模与预测流程。`CASE1` 用于完整数据库 3D 建模验证；`CASE2-1` 用于同一稀疏数据条件下的 3D 建模与流量已知预测；`CASE2-2` 用于验证 `1D + 2D` 方法；`CASE2-3` 用于验证 `1D + 3D` 方法。

技术报告正文中建议重点呈现四个算例的分区交叉验证结果、方法二与方法三的差异，以及程序模型名称与代理模型理论名称的对应关系。使用手册则用于说明数据格式、配置方法、关键脚本和复现步骤。
