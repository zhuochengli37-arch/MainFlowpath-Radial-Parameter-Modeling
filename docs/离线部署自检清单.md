# 离线部署自检清单

## 1. 使用说明

本清单用于你在离线机上部署完成后，逐项确认环境是否真的可用。

建议使用方法：

1. 先完成 Python 安装；
2. 再完成 `deploy_offline.ps1` 部署；
3. 然后一条一条执行本清单中的检查项。

## 2. 复制内容检查

确认以下内容已经从联网机复制到离线机：

- 项目根目录；
- `offline_packages/`；
- `offline_installers/python-3.10.10.exe`；
- `config/`；
- `data/`；
- `workbase/`；
- `docs/`；
- `project1/`。

确认以下内容不是必须复制的：

- 联网机器已有的 `.venv`

## 3. Python 安装检查

执行：

```powershell
D:\python310\python.exe --version
```

通过标准：

- 能输出 Python 版本；
- 版本与 `offline_packages/offline_manifest.json` 一致；
- 当前项目建议版本为 `3.10.10`。

## 4. 离线包完整性检查

确认以下内容存在：

- `offline_packages/offline_manifest.json`
- `offline_packages/` 中的 `pip`
- `offline_packages/` 中的 `setuptools`
- `offline_packages/` 中的 `wheel`
- `offline_packages/` 中的 `numpy`
- `offline_packages/` 中的 `scipy`
- `offline_packages/` 中的 `scikit-learn`
- `offline_packages/` 中的 `xgboost`
- `offline_packages/` 中的 `lightgbm`
- `offline_packages/` 中的 `PyYAML`
- `offline_packages/` 中的 `tqdm`

## 5. 部署命令检查

### 5.1 默认部署方式

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File "workbase/tools/deployment/deploy_offline.ps1" -PythonExe "D:\python310\python.exe"
```

### 5.2 如果项目根目录写权限不稳定

改用：

```powershell
powershell -ExecutionPolicy Bypass -File "workbase/tools/deployment/deploy_offline.ps1" -PythonExe "D:\python310\python.exe" -VenvPath "$env:TEMP\project1_offline"
```

通过标准：

- 脚本没有中途致命退出；
- 输出中出现 `Python version matches offline manifest.`；
- 输出中出现 `Core dependencies imported successfully.`；
- 输出中出现 `Entrypoint check passed.`。

说明：

- 即使使用 `TEMP` 目录虚拟环境，现在也支持直接运行脚本；
- 一般不必额外传 `-InstallEditable`。

## 6. 虚拟环境解释器检查

### 6.1 如果你部署到默认 `.venv`

执行：

```powershell
.\.venv\Scripts\python.exe --version
```

### 6.2 如果你部署到 `TEMP`

执行：

```powershell
$env:TEMP\project1_offline\Scripts\python.exe --version
```

通过标准：

- 能正确输出 Python 版本；
- 解释器路径确实来自你刚部署的虚拟环境。

## 7. 核心依赖导入检查

默认 `.venv`：

```powershell
.\.venv\Scripts\python.exe -c "import numpy, scipy, sklearn, yaml, tqdm, xgboost, lightgbm; print('deps-ok')"
```

`TEMP` 虚拟环境：

```powershell
$env:TEMP\project1_offline\Scripts\python.exe -c "import numpy, scipy, sklearn, yaml, tqdm, xgboost, lightgbm; print('deps-ok')"
```

通过标准：

- 输出 `deps-ok`；
- 没有 `ModuleNotFoundError`；
- 没有版本不匹配导致的导入失败。

## 8. 统一入口检查

默认 `.venv`：

```powershell
.\.venv\Scripts\python.exe -m project1 --help
.\.venv\Scripts\python.exe -m project1 current --help
.\.venv\Scripts\python.exe -m project1 generic --help
```

`TEMP` 虚拟环境：

```powershell
$env:TEMP\project1_offline\Scripts\python.exe -m project1 --help
```

通过标准：

- 能正常显示帮助；
- 不出现导入报错；
- 说明统一入口可用。

## 9. 直接运行脚本检查

如果你和现在一样，更习惯直接运行脚本，那么这一项必须检查。

### 9.1 当前项目脚本检查

默认 `.venv`：

```powershell
.\.venv\Scripts\python.exe workbase/current_scripts/predict_1d.py
.\.venv\Scripts\python.exe workbase/current_scripts/predict_3d.py
.\.venv\Scripts\python.exe workbase/current_scripts/workline_pipeline.py --mode predict
```

### 9.2 通用脚本检查

默认 `.venv`：

```powershell
.\.venv\Scripts\python.exe workbase/generic_scripts/generic_predict_1d.py
```

如果你部署到 `TEMP`，只需要把解释器前缀改为：

```powershell
$env:TEMP\project1_offline\Scripts\python.exe
```

通过标准：

- 脚本能启动；
- 不会误切换到错误解释器；
- 日志能写入；
- 输出目录能生成结果。

## 10. IDE 检查

如果你在 PyCharm 中运行，请确认：

1. `Python Interpreter` 指向你部署好的虚拟环境；
2. `Working Directory` 是项目根目录；
3. 运行配置没有误指向系统 Python。

通过标准：

- 点运行后脚本直接工作；
- 不出现 `No module named ...`；
- 不出现解释器切换错误。

## 11. 输出结果检查

请检查：

- `logs/` 目录有新的日志文件；
- 输出目录有新的结果文件；
- 没有明显的致命报错；
- 没有误用系统 Python。

## 12. 常见故障快速判断

### 12.1 出现 `Python version mismatch`

处理：

1. 改用 `3.10.10`；
2. 或重新打离线依赖包。

### 12.2 出现 `No module named 'yaml'`

处理：

1. 检查 `PyYAML` 是否在 `offline_packages/`；
2. 重新执行 `deploy_offline.ps1`。

### 12.3 出现 `No module named 'tqdm'`

处理：

1. 检查 `tqdm` 是否在 `offline_packages/`；
2. 重新执行部署脚本。

### 12.4 项目根目录 `.venv` 创建失败

处理：

直接改用：

```powershell
powershell -ExecutionPolicy Bypass -File "workbase/tools/deployment/deploy_offline.ps1" -PythonExe "D:\python310\python.exe" -VenvPath "$env:TEMP\project1_offline"
```

### 12.5 加了 `-InstallEditable` 但出现 warning

只要以下三项正常，通常仍可继续使用：

1. 依赖已安装；
2. `python -m project1 --help` 能正常运行；
3. 你常用脚本能直接运行。

## 13. 通过标准

满足以下条件后，可认为离线部署合格：

1. Python 版本正确；
2. 部署脚本完成；
3. 核心依赖导入成功；
4. 统一入口可用；
5. 你常用的脚本可直接运行；
6. 日志和输出路径都能正常写入。
