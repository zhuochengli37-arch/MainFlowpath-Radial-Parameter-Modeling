# 方法二与方法三预测指南

## 1. 适用范围

本文说明当前项目中两种“预测阶段缺少真实 `wcor`”时的处理方法：

- 方法二：`1D + 2D`
- 方法三：`1D + 3D`

两种方法都使用领域专用配置文件：

```text
config/benchmark_config.yaml
```

推荐通过统一入口执行：

```powershell
python -m project1 current ...
```

## 2. 两种方法的核心区别

### 2.1 方法二：1D + 2D

方法二适用于预测输入只有 `rpm` 和 `xi`，并希望直接用二维状态关系预测 `psi / tsi / mai` 的情况。

基本流程为：

1. 用 1D 模型预测 `rpm -> wcor`
2. 用 2D 模型预测 `(rpm, xi) -> outputs`
3. 将 1D 与 2D 的结果合并

方法二的优势是流程清晰，并且已经有一键脚本：

```powershell
python workbase/current_scripts/workline_pipeline.py
```

需要注意的是，方法二强依赖 2D 分区样本量。如果某个分区训练样本太少，即使预测文件里只有一两个点本身没有问题，2D 模型也可能无法稳定训练或无法用于预测。

### 2.2 方法三：1D + 3D

方法三适用于预测输入只有 `rpm` 和 `xi`，但项目中已经有成熟 3D 模型可复用的情况。

基本流程为：

1. 用 1D 模型预测 `rpm -> wcor`
2. 将预测得到的 `wcor` 写入中间结果
3. 用 3D 模型预测 `(rpm, wcor, xi) -> outputs`

方法三的主预测能力来自 3D 模型。对于 `CASE2` 这类稀疏数据，如果 2D 分区样本不足，方法三通常比方法二更稳妥。

当前项目中没有单独的“一键 `1D + 3D`”脚本，推荐按顺序手动执行：

```powershell
python -m project1 current predict-1d
python -m project1 current predict-3d
```

## 3. 数据组织规则

### 3.1 训练数据

无论使用方法二还是方法三，训练阶段都建议保留完整结构化 3D 数据。

推荐结构如下：

```text
data/current/3d/<数据集名>/train/
  DATABASE_CMP/
    STAGE_1/
      RPM_0.6/
        0.00436.txt
  DATABASE_HTB/
    STAGE_1/
      0.555/
        0.01509.txt
```

文件内容示例：

```text
xi psi tsi mai
0.000000e+00 ...
2.040816e-02 ...
```

程序会按工作流自动抽取不同特征：

- `benchmark_1d` 提取 `rpm -> wcor`
- `benchmark_2d` 提取 `(rpm, xi) -> outputs`
- `benchmark_3d` 提取 `(rpm, wcor, xi) -> outputs`

其中，`benchmark_1d` 按部件和级号分别提取、交叉验证并训练流量模型，不会将不同部件的数据混合训练。若同一分区内同一 `rpm` 对应多个 `wcor`，则该分区不满足单值 `rpm -> wcor` 关系，程序会拒绝训练流量模型。

其中，`STAGE_*` 下一级目录既可以写成 `RPM_0.555`，也可以写成纯数字目录 `0.555`。程序会把这一级识别为 `rpm`。

### 3.2 方法二预测数据

方法二预测阶段推荐输入显式包含：

```text
rpm xi
```

推荐目录结构：

```text
data/current/3d/CASE2-2/predict/
  DATABASE_CMP/
    STAGE_1/
      RPM_0.6/
        sample1.txt
  DATABASE_HTB/
    STAGE_1/
      0.555/
        sample2.txt
```

文件内容示例：

```text
rpm xi
0.555 0.000000
0.555 0.163401
0.555 0.295308
```

虽然程序可以从路径中解析部分信息，但预测文件中显式写出 `rpm` 和 `xi` 最稳妥。

### 3.3 方法三预测数据

方法三预测阶段同样推荐输入显式包含：

```text
rpm xi
```

但方法三还有一个额外要求：**预测文件名不能继续使用数值型 `wcor` 文件名**。

不推荐：

```text
DATABASE_HTB/STAGE_1/0.555/0.01509.txt
```

原因是 3D 预测阶段会继续从路径和文件名解析元数据。如果文件名仍像真实 `wcor`，程序可能把它当作真实流量值，从而覆盖 `predict-1d` 预测出的 `wcor`。

推荐：

```text
DATABASE_HTB/STAGE_1/0.555/0.555_predict.txt
DATABASE_CMP/STAGE_1/RPM_0.6/RPM_0.6_predict.txt
```

## 4. 方法二配置与执行

以下以 `CASE2-2` 为例：

```yaml
benchmark_1d:
  paths:
    input: "./data/current/3d/CASE2-2/train"
    output: "./data/current/3d/CASE2-2/output_1d"

benchmark_2d:
  paths:
    input: "./data/current/3d/CASE2-2/train"
    output: "./data/current/3d/CASE2-2/output_2d"

predict_1d:
  paths:
    input: "./data/current/3d/CASE2-2/predict"
    model_output: "./data/current/3d/CASE2-2/output_1d"
    output: "./data/current/3d/CASE2-2/results_1d"

predict_2d:
  paths:
    input: "./data/current/3d/CASE2-2/predict"
    model_output: "./data/current/3d/CASE2-2/output_2d"
    output: "./data/current/3d/CASE2-2/results_2d"
```

一键执行：

```powershell
python workbase/current_scripts/workline_pipeline.py
```

分步执行：

```powershell
python -m project1 current benchmark-1d
python -m project1 current benchmark-2d
python -m project1 current predict-1d
python -m project1 current predict-2d
```

典型输出位置：

- 1D 模型：`benchmark_1d.paths.output`
- 2D 模型：`benchmark_2d.paths.output`
- 1D 预测结果：`predict_1d.paths.output`
- 2D 预测结果：`predict_2d.paths.output`
- 合并结果：`results_2d_merged/`

## 5. 方法三配置与执行

以下以 `CASE2-3` 为例，假设 1D 模型复用 `CASE2-2/output_1d`，3D 模型复用同一组稀疏数据训练得到的 `CASE2-1/output`：

```yaml
predict_1d:
  paths:
    input: "./data/current/3d/CASE2-3/predict"
    model_output: "./data/current/3d/CASE2-2/output_1d"
    output: "./data/current/3d/CASE2-3/results_1d"

predict_3d:
  paths:
    input: "./data/current/3d/CASE2-3/results_1d"
    model_output: "./data/current/3d/CASE2-1/output"
    output: "./data/current/3d/CASE2-3/results_3d"
```

如果已经有可复用的 1D 模型：

```powershell
python -m project1 current predict-1d
python -m project1 current predict-3d
```

如果还没有 `rpm -> wcor` 的 1D 模型：

```powershell
python -m project1 current benchmark-1d
python -m project1 current predict-1d
python -m project1 current predict-3d
```

执行时需要确认：

- `benchmark_1d.paths.input` 指向用于训练 1D 模型的数据
- `benchmark_1d.paths.output` 指向要保存 1D 模型的目录
- `predict_1d.paths.model_output` 指向已经训练好的 1D 模型目录
- `predict_3d.paths.model_output` 指向已经训练好的 3D 模型目录

## 6. 为什么 `results_1d` 可以直接作为 3D 输入

`predict-1d` 不会覆盖原始 `predict/` 文件，而是将补入预测 `wcor` 后的新文件写到 `results_1d/`。

方法三的数据流为：

1. 原始输入：`CASE2-3/predict`
2. 运行 `predict-1d`：输出到 `CASE2-3/results_1d`
3. 运行 `predict-3d`：直接读取 `CASE2-3/results_1d`

即使中间文件的列顺序显示为：

```text
rpm xi wcor
```

也不会影响 3D 预测。`predict-3d` 按列名识别 `rpm / wcor / xi`，不是按固定列位置读取。

## 7. 什么时候选择哪种方法

更适合方法二的情况：

- 2D 分区样本量充足
- 希望用 `(rpm, xi)` 独立预测主性能
- 希望使用已有的 `workline_pipeline.py` 一键流程

更适合方法三的情况：

- 已经有可靠的 3D 模型
- 当前预测数据缺少真实 `wcor`
- 某些分区的 2D 样本太少，无法稳定训练 2D 模型
- 希望复用与当前稀疏场景一致的 3D 模型；在本项目 `CASE2` 组内，对应 `CASE2-1/output`

## 8. 常见问题

### 8.1 `predict/` 里只放一两个点可以吗

可以。预测阶段只依赖已经训练好的模型，预测文件点数少并不会阻止程序运行。真正需要关注的是训练数据是否足够支撑对应模型。

### 8.2 为什么方法三必须修改数值型文件名

因为文件名如果仍像 `0.01509.txt`，程序可能把它当作真实 `wcor`，从而覆盖 1D 模型预测出的 `wcor`。

### 8.3 方法三会不会改写原始预测文件

不会。`predict-1d` 会把补充了 `wcor` 的中间文件写到 `results_1d/`，原始 `predict/` 目录保持不变。

## 9. 使用建议

- 方法二适合 2D 数据充足、希望形成标准化 workline 流程的场景。
- 方法三适合快速复用成熟 3D 模型，尤其适合稀疏 `CASE2` 类数据。
- 如果后续频繁使用方法三，可以新增一个串联脚本，把 `predict-1d -> predict-3d` 固化为一键流程。
