## 运行前最少检查

每次换数据集运行前，建议先检查这些项：

1. `dataset_schema.inputs`
2. `dataset_schema.targets`
3. `dataset_schema.source_priority`
4. `dataset_schema.aliases`
5. 对应流程的 `paths.input`
6. 对应流程的 `paths.output`
7. 预测流程的 `paths.model_output`
8. `partition_mode` 或 `partition`

## dataset_schema

`dataset_schema` 定义数据字段的含义，是最重要的一段配置。

### inputs

```yaml
dataset_schema:
  inputs: ["rpm", "wcor", "xi"]
```

`inputs` 定义输入变量的逻辑顺序。

- 3D 训练使用第 1、2、3 个输入：`rpm, wcor, xi`
- 2D 训练使用第 1、3 个输入：`rpm, xi`
- workline 训练使用第 1 个输入预测第 2 个输入：`rpm -> wcor`
- 1D 训练会优先使用配置中的输入字段匹配文件列

变量名可以不是 `xi`。例如第三个输入叫 `span`：

```yaml
dataset_schema:
  inputs: ["rpm", "wcor", "span"]
```

程序内部有些历史属性仍叫 `xi`，但读取时会使用 `inputs[2]` 对应的字段。

### targets

```yaml
dataset_schema:
  targets: ["psi", "tsi", "mai"]
```

`targets` 定义要训练和预测的输出变量。

如果不同数据库包含的输出变量数量不一致，推荐把所有可能目标写全：

```yaml
dataset_schema:
  targets: ["psi", "tsi", "mai", "pi", "ti", "eta"]
```

不同文件可以只包含其中一部分目标。训练时会从实际加载到的样本里动态汇总目标，不要求每个数据库都有全部目标。

也可以设置成自动识别：

```yaml
dataset_schema:
  targets: []
```

此时程序会把非输入列、非元数据列都当作输出目标。这个方式更省事，但如果文件里有辅助列、编号列、标志列，可能被误当作目标。工程数据中通常更推荐显式列出目标。

### metadata

```yaml
dataset_schema:
  metadata: ["component", "stage", "database"]
```

`metadata` 是样本元信息。当前主要用于分区、结果组织和模型元数据。

常用字段：

- `component`：部件名，例如 `CMP`、`HPTB`、`NOZZLE`
- `stage`：级数，例如 `1`
- `database`：数据库或目录名，例如 `DATABASE_CMP`

### source_priority

```yaml
dataset_schema:
  source_priority:
    component: ["path", "column"]
    stage: ["path", "column"]
    database: ["path", "column"]
    rpm: ["path", "column"]
    wcor: ["path", "column"]
    xi: ["column"]
```

`source_priority` 控制字段优先从哪里读取。

- `path`：从目录或文件名解析
- `column`：从文件列读取

如果你的 `rpm`、`wcor` 名称或路径格式不统一，建议优先从列读取：

```yaml
dataset_schema:
  source_priority:
    rpm: ["column", "path"]
    wcor: ["column", "path"]
```

当前路径解析默认支持这类格式：

```text
DATABASE_CMP/STAGE_1/RPM_0.650/0.006810.dat
DATABASE_CMP/STAGE_1/RPM_0.650/WCOR_0.006810.dat
DATABASE_CMP/STAGE_1/RPM_0.650/PHI_0.006810.dat
```

如果路径写成 `N_0.650/FLOW_0.006810.dat`，当前不会自动识别为 `rpm/wcor`。这种情况建议把 `rpm/wcor` 放进文件列里，或者扩展路径解析代码。

### aliases

```yaml
dataset_schema:
  aliases:
    rpm: ["rpm"]
    wcor: ["wcor"]
    xi: ["xi"]
    psi: ["psi"]
    tsi: ["tsi"]
    mai: ["mai"]
```

`aliases` 用于解决列名不统一的问题。左边是逻辑名，右边是实际文件里可能出现的列名。

例如不同文件中输入列有不同命名：

```yaml
dataset_schema:
  inputs: ["rpm", "wcor", "span"]
  targets: ["pi", "ti"]

  aliases:
    rpm: ["rpm", "RPM", "n", "speed", "rotor_speed"]
    wcor: ["wcor", "WCOR", "phi", "flow", "mass_flow"]
    span: ["xi", "span", "r"]
    pi: ["pi", "pressure_ratio"]
    ti: ["ti", "temperature_ratio"]
    component: ["component", "part", "module"]
    stage: ["stage", "stage_id"]
    database: ["database", "db"]
```

如果部件名不是从 `DATABASE_...` 目录读取，而是在文件列里，建议给 `component` 也配置别名。

### missing_value_sentinels

```yaml
dataset_schema:
  missing_value_sentinels: [-999.0]
```

这些值会被当作缺失目标，而不是真实数值。

例如：

```text
xi pi     ti
0  -999.0 1.3
1  -999.0 0.8
```

训练时：

- `pi` 不使用这两行
- `ti` 使用这两行
- `xi` 仍然必须是真实输入值

缺失值处理是按目标单独过滤，不是整行全部丢弃。只有当某行没有任何有效目标时，这一行才不会形成训练样本。

### partition

```yaml
dataset_schema:
  partition:
    mode: "config"
    keys: ["component", "stage"]
```

这段是 schema 层的分区扩展配置。

当前常用方式仍是通过 `benchmark_3d.partition_mode` 或 `benchmark_2d.partition_mode` 控制分区。

## 训练配置快照

`benchmark_1d.py`、`benchmark_2d.py`、`benchmark_3d.py` 每次训练成功后，都会把本次使用的
`config/benchmark_config.yaml` 复制到训练输出目录。

输出包括两份：

- `run_config_latest.yaml`：最新一次训练配置，会被下一次成功训练覆盖
- `run_configs/benchmark_config_YYYYMMDD_HHMMSS.yaml`：带时间戳的历史配置快照，不会被覆盖

如果同一秒内连续写入多个快照，历史文件会自动追加 `_1`、`_2` 这样的后缀。
后续想复现某次训练时，应优先找对应时间的历史快照，再配合当时的输入数据和代码版本运行。

## partition_mode

`partition_mode` 控制训练时如何拆分数据和保存模型。

常用值：

- `single` 或 `none`：所有样本合成一个分区
- `component`：按部件分区
- `multi` 或 `component_stage`：按部件和级数分区，当前推荐
- `family`：按部件家族分区

### 如何选择

一般优先使用：

```yaml
partition_mode: "multi"
```

`multi` 会把不同部件、不同级数分开训练，适合各级性能规律不完全相同的工程数据。

如果数据量太少，导致每个 `component + stage` 分区样本不足，可以退一步使用：

```yaml
partition_mode: "component"
```

这样同一个部件下的多个级会合并训练，样本数会更多，但会牺牲一部分分级差异。

如果你明确希望所有部件、所有级都混在一起训练，或者数据太少无法再分区，可以使用：

```yaml
partition_mode: "single"
```

这种方式会训练一个整体模型，最省样本，但也最容易把不同部件、不同级数的物理规律混在一起。

如果你希望把相似部件合并成家族，例如：

```text
CMP / FAN     -> compressor
HPTB / LPTB   -> turbine
CC / COMB     -> combustor
```

可以使用：

```yaml
partition_mode: "family"
```

这种方式适合部件名称不同但物理类别相近、且你希望共享训练样本的情况。

例如 `multi` 会生成：

```text
CMP:S1
CMP:S2
HPTB:S1
```

模型目录中会把冒号转换成下划线：

```text
models/CMP_S1/
models/CMP_S2/
models/HPTB_S1/
```

## 部件名规则

如果从路径读取部件名，推荐使用：

```text
DATABASE_CMP/
DATABASE_HPTB/
DATABASE_NOZZLE/
```

程序会把 `DATABASE_` 后面的内容作为 `component`。

如果从列读取部件名，可以配置：

```yaml
dataset_schema:
  source_priority:
    component: ["column", "path"]
  aliases:
    component: ["component", "part", "module"]
```

`partition_mode: "family"` 时，部件家族识别规则在代码中：

- 包含 `CMP` 或 `FAN` -> `compressor`
- 包含 `TB` 或 `TURB` -> `turbine`
- 包含 `CC`、`COMB` 或 `BURNER` -> `combustor`
- 其它 -> 使用部件名自己作为 family

