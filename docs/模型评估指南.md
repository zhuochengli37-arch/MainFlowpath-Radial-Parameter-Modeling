# 模型评估指南

## 1. 文档目的

本文说明 `AIR2 Project1` 当前模型评估体系的核心逻辑，包括：

- 常用误差指标；
- 交叉验证策略；
- split mode 的意义；
- 分区评估方式；
- 报告的解读方法；
- 当前推荐的模型选择思路。

## 2. 核心评估指标

### 2.1 RMSE

`RMSE` 是当前最常用的主指标，特点是对大误差更敏感。

适合场景：

- 关心大偏差；
- 希望把严重误差放大处理；
- 作为工程上的主排序指标。

### 2.2 MAE

`MAE` 反映平均绝对误差，更稳健，不像 `RMSE` 那样放大大误差。

适合场景：

- 关注整体平均误差；
- 希望减少异常点对排序的影响。

### 2.3 MAPE

`MAPE` 反映相对误差，适合比较不同量纲或不同量级目标的误差表现。

适合场景：

- 关心相对误差；
- 需要在多个目标量之间比较“相对好坏”。

注意：

- 当真实值非常接近 0 时，`MAPE` 稳定性会变差。

### 2.4 R2

`R2` 用于衡量拟合解释能力，越接近 `1` 通常表示拟合越好。

适合场景：

- 辅助判断整体拟合质量；
- 作为解释型指标参考，而不是唯一主排序指标。

## 3. 交叉验证策略

### 3.1 K 折交叉验证

项目中的 benchmark 通常使用 K 折交叉验证。

基本思路：

1. 将数据分成 K 份；
2. 轮流使用其中 1 份做验证；
3. 其余 K-1 份做训练；
4. 最终对 K 次结果求平均。

### 3.2 当前使用建议

- 样本较多：优先 `5` 折；
- 样本较少：可退到 `3` 折；
- 对每个目标列，程序会根据可用样本数自适应实际折数。

## 4. split mode 的意义

当前 3D benchmark 会重点使用三种 split mode：

- `random`
- `rpm`
- `wcor`

### 4.1 `random`

随机划分训练集和验证集。

适合判断：

- 模型在已知样本分布中的插值能力；
- 整体拟合水平。

### 4.2 `rpm`

按转速分组，确保某些 `rpm` 不同时出现在训练和验证中。

适合判断：

- 对新转速工况的外推能力。

### 4.3 `wcor`

按流量分组，确保某些 `wcor` 不同时出现在训练和验证中。

适合判断：

- 对新流量工况的外推能力。

## 5. 分区评估方式

### 5.1 为什么要分区

不同部件、不同级数的数据规律差异明显，全部混合训练常常会降低表现。

因此项目支持分区训练与评估。

### 5.2 常用分区模式

- `single`：全部样本混合；
- `component`：按部件分区；
- `multi`：按部件 + 级数分区，当前推荐；
- `family`：按部件家族分区。

### 5.3 当前推荐

工程数据通常优先使用：

```yaml
partition_mode: "multi"
```

这样更容易保留各部件、各级数的局部规律。

## 6. 当前报告结构解读

当前 3D Markdown 报告已经统一为以下结构：

1. 真实样本数说明；
2. 按部件或分区的汇总；
3. 先输出按 `RMSE` 的整体最佳模型；
4. 再输出按 `MAPE` 的整体最佳模型；
5. 再按 `RMSE` 从优到差列出全部模型；
6. 再按 `MAPE` 从优到差列出全部模型。

### 6.1 样本数说明

现在报告顶部使用的是真实样本数，不再把所有模型的样本数重复累计。

### 6.2 为什么有两套“最佳模型”

因为：

- `RMSE` 更偏向控制大误差；
- `MAPE` 更偏向控制相对误差。

在工程上，两者有时会选出不同模型，因此报告会同时保留两种最佳结果。

## 7. 当前模型选择建议

### 7.1 默认建议

如果没有更强的业务偏好，当前推荐优先看：

- `selection_split_mode=random`
- `selection_metric=rmse`

### 7.2 什么时候看 `MAPE`

当你更关心相对误差时，应重点看：

- 报告中的 `MAPE` 最佳模型；
- 排名中的 `MAPE` 完整排序。

### 7.3 什么时候更看重 `rpm` / `wcor`

当你实际业务更像“预测没见过的新工况”时，应重点关注：

- `rpm` split 结果；
- `wcor` split 结果；
- 而不是只看 `random`。

## 8. 评估结果的实用读取顺序

建议按下面顺序看结果：

1. 先看真实样本数和分区方式；
2. 再看 `RMSE` 整体最佳模型；
3. 再看 `MAPE` 整体最佳模型；
4. 然后查看完整排序，确认是否存在多个性能接近的候选模型；
5. 如果用于外推，再回到 `rpm` / `wcor` split 结果看稳定性。

## 9. 常见问题

### 9.1 为什么 `random` 往往比 `rpm` / `wcor` 好？

因为 `random` 更像“已知分布内插值”，而 `rpm` / `wcor` 更接近外推，通常更难。

### 9.2 为什么不同目标量最佳模型可能不同？

因为每个目标量的变化规律不同，项目本来就是按目标列分别评估和选模。

### 9.3 是否必须所有目标共用同一个模型？

当前不是。默认是每个目标量独立选择最佳模型。
