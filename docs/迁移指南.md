# 入口迁移指南

## 1. 迁移目标

项目已经完成统一入口建设，当前推荐从历史脚本入口迁移到：

```powershell
python -m project1 current ...
python -m project1 generic ...
```

这次迁移的重点是统一入口和使用习惯，不是重写业务逻辑。

## 2. 迁移后哪些东西不变

迁移到统一入口后，下面这些通常不需要变：

- 配置文件位置
- 数据目录结构
- 模型输出路径
- 报告输出路径
- 训练与预测的核心行为

也就是说，大多数情况下改的是“怎么启动”，不是“怎么组织数据”。

## 3. 常用命令迁移对照

### 3.1 current 领域专用工作流

| 兼容脚本入口 | 当前推荐入口 |
|---|---|
| `python workbase/current_scripts/benchmark_1d.py` | `python -m project1 current benchmark-1d` |
| `python workbase/current_scripts/predict_1d.py` | `python -m project1 current predict-1d` |
| `python workbase/current_scripts/benchmark_2d.py` | `python -m project1 current benchmark-2d` |
| `python workbase/current_scripts/predict_2d.py` | `python -m project1 current predict-2d` |
| `python workbase/current_scripts/benchmark_3d.py` | `python -m project1 current benchmark-3d` |
| `python workbase/current_scripts/predict_3d.py` | `python -m project1 current predict-3d` |
| `python workbase/current_scripts/workline_pipeline.py` | 方法二一键串联：`benchmark-1d + benchmark-2d + predict-1d + predict-2d` |

### 3.2 generic 通用工作流

| 兼容脚本入口 | 当前推荐入口 |
|---|---|
| `python workbase/generic_scripts/generic_benchmark_1d.py` | `python -m project1 generic benchmark-1d` |
| `python workbase/generic_scripts/generic_predict_1d.py` | `python -m project1 generic predict-1d` |
| `python workbase/generic_scripts/generic_benchmark_2d.py` | `python -m project1 generic benchmark-2d` |
| `python workbase/generic_scripts/generic_predict_2d.py` | `python -m project1 generic predict-2d` |
| `python workbase/generic_scripts/generic_benchmark_3d.py` | `python -m project1 generic benchmark-3d` |
| `python workbase/generic_scripts/generic_predict_3d.py` | `python -m project1 generic predict-3d` |

## 5. 迁移后的使用建议

### 5.1 先确认帮助能打开

```powershell
python -m project1 --help
python -m project1 current benchmark-3d --help
python -m project1 generic benchmark-2d --help
```

### 5.2 建议优先迁移的命令

建议先把最常用、最稳定的主流程迁到统一入口：

1. `benchmark-1d`
2. `predict-1d`
3. `benchmark-3d`
4. `predict-3d`
5. `generic benchmark/predict`

### 5.3 方法二场景怎么理解

如果你原来习惯把这条链路叫做 “2D + workline”，现在建议统一理解为：

- 方法二：`1D + 2D`

对应关系是：

```powershell
python -m project1 current benchmark-1d
python -m project1 current benchmark-2d
python -m project1 current predict-1d
python -m project1 current predict-2d
```

如果想一键执行，直接使用：

```powershell
python workbase/current_scripts/workline_pipeline.py
```

### 5.4 如果你主要在 IDE 中运行

如果你不想改成手敲命令，也可以这样理解迁移：

1. 文档和帮助统一看 `python -m project1 ...`
2. 日常点运行仍可继续用 `workbase/current_scripts/*.py` 或 `workbase/generic_scripts/*.py`
3. 真正需要迁移的是数据目录和配置习惯，不是必须改成纯命令行工作

## 6. 迁移验收建议

迁移后建议至少检查：

1. `--help` 是否正常显示
2. 配置文件路径是否仍然正确
3. 训练输出目录是否符合预期
4. 预测结果目录是否符合预期
5. 如果改动较大，执行 `python workbase/tools/regression/run_regression_suite.py`

## 7. 常见问题

### 7.1 为什么还保留兼容脚本

为了平滑迁移、回归验证和 IDE 点运行体验。

当前策略不是强制切断旧入口，而是：

- 统一新入口
- 保留兼容脚本

### 7.2 迁移后需要改配置吗

通常不需要。  
大多数情况下只改启动方式，不改配置内容。

### 7.3 迁移后输出路径会变化吗

通常不会。  
统一入口主要改变的是调用方式，不主动改变输出结构。
