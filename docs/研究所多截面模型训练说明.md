# 研究所 Multi-Section 模型训练说明

## 范围

当前阶段将 `institute_multi_section / v1` 及其正式四截面兼容标识接入现有领域专用
1D、2D、3D训练核心。没有新增或修改回归算法、候选模型、交叉验证规则、指标、
`max_samples`位置或模型超参数。Multi-Section预测、结果重组、workline预测串联及AI
模型均未接入。

只有 `station=MAIN` 可进入训练。INLET/OUTLET继续可以识别和解析，但不会形成训练样本。

## 数据进入训练的路径

径向训练使用显式Schema dispatcher：

```text
raw file
  -> header/schema识别
  -> Multi-Section Adapter
  -> CanonicalMultiSectionData
  -> 按section展开为FlexSample(section=...)
  -> 径向partition
  -> 现有2D/3D数组、CV、模型工厂、指标与最终拟合
```

原有 `load_samples()`仍只处理Legacy和Single-Section，保证其准入边界与行为稳定。
Multi-Section由独立 `load_multi_section_samples()`处理，再由训练专用dispatcher汇合；
预测加载器未改为接收Multi-Section。

## 1D工况加载与分区

1D继续定义为：

```text
speed_parameter -> flow_parameter
partition = component + stage
```

`load_operating_conditions()`只读取路径/header/schema和工况metadata，每个MAIN源文件输出
一条记录，不读取或展开section径向数组。因此，一个M-section宽表不会产生M倍1D样本。
现有按partition、speed去重逻辑继续复用；同一partition同一speed对应不同flow时仍明确
报错。

训练输出新增 `operating_conditions_manifest.json`，记录每个1D partition的源文件数、
工况记录数、唯一speed-flow点数和冲突计数。

## 2D/3D径向分区

统一分区规则是：

```text
Single-Section: component + stage
Multi-Section:  component + stage + section
```

例如Single的 `CMP:S1`及模型目录 `CMP_S1`保持不变；Multi的RI模型使用
`CMP:S1:RI`及目录 `CMP_S1_RI`。section来自数据，不限定为RI/RO/SI/SO。

section只作为离散partition维度，不作为连续输入。现有数组核心直接复用：

```text
2D: speed_parameter + xi -> target
3D: speed_parameter + flow_parameter + xi -> target
```

每个section的xi独立保留，不对齐、不插值、不重采样。

## 动态targets

数据库的available outputs与训练selected targets分开记录：

- `targets: auto`：每个partition选择其所有结构性可用outputs；
- `targets: [Cpt, Ctt, MA]`：只训练显式选择且该partition完整提供的targets；
- `missing_target_policy: error`：结构性不一致或指定target缺失时停止并报告；
- `missing_target_policy: skip`：跳过不完整target，并在target plan中记录原因。

未知但合法的变量（例如 `Alpha`）可以通过 `auto`或显式列表进入训练，不需要新增
component条件分支。`-999`等missing-value sentinel仍按target逐行过滤；它不等同于
header中没有该输出字段。

## 模型文件与可追溯信息

每个模型旁的JSON metadata新增兼容性的 `model_context`，至少记录：

```text
model_dimension, component, stage, station, section, partition
schema_name, schema_version, inputs, target
speed_parameter_source_name, flow_parameter_source_name
training_source_root, training_sources, sample_count
available_outputs, selected_targets  # 2D/3D
```

旧metadata字段和读取方式保持不变。leaderboard与models manifest增加结构化identity、
模型路径、样本数和指标；路径用于组织，metadata用于自描述，两者不能互相替代。

## 正式数据库验证

2026-09-04对 `04_TEST_DATA/DATABASE-四个截面`完成训练前审计：400个文件全部可解析，
其中MAIN 240、INLET 80、OUTLET 80；形成240条1D工况记录、12个1D partition，
每个partition均有20个唯一speed-flow点且无同speed多flow冲突。径向展开得到10560条样本、
48个 `component + stage + section` partition，每个partition 220条样本和20个源文件。

另以CMP第1级正式数据执行受控快速训练：1D保存1个测试候选模型；2D和3D均识别4个
section、880条径向样本，并分别保存24个模型（4 section × 6 targets × 1测试候选）。
该运行保留原有CV、最终拟合、保存、metadata及manifest代码路径，仅将候选集限制为一个
线性模型以控制耗时。它只验证训练链路可运行，不代表代理模型精度。
