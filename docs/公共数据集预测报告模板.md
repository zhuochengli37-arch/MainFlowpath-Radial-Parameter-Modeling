# 公开数据库预测结果技术报告模板

## 1. 文档用途

本文档提供一份适用于“公开数据库预测结果”写入项目总结报告时的正式技术报告模板。  
模板重点说明以下内容：

1. 数据来源与任务定义应如何写；
2. 模型、输入、输出和运行条件应如何交代；
3. 预测结果应如何展示；
4. **验证过程应如何说明**；
5. 如何区分“插值能力验证”与“外推能力验证”。

适用场景包括：

- 使用 `data/current` 下的正式算例完成训练与预测；
- 使用 `data/generic` 下的通用样例完成公开表格数据预测；
- 将预测结果、误差统计和图表整理到项目总结报告、阶段汇报或结题材料中。

---

## 2. 推荐写作原则

在总结报告中写“公开数据库预测结果”时，建议遵循以下原则：

1. **先交代验证任务，再展示结果**，不要只给出一组误差数字；
2. **先说明验证依据，再说明模型优劣**，避免“只报好结果、不报验证方式”；
3. **明确训练集、验证集、测试集或外部对照集的来源**；
4. **明确评价指标及其物理意义**，至少说明 `RMSE`、`MAE`、`MAPE`、`R²` 中使用了哪些；
5. **明确预测样本是否落在训练分布内**，即区分插值验证与外推验证；
6. **明确结果可复现依据**，如配置文件、模型元数据、排行榜、输出报告和配置快照。

---

## 3. 正式报告模板

以下模板可直接复制到项目总结报告中，再按具体算例替换方括号内容。

### 3.1 章节标题模板

`X.X 公开数据库预测结果验证`

### 3.2 正文模板

#### （1）验证目的

为验证所建模型在公开数据库样本上的预测能力，本阶段选取 `[数据集名称]` 作为对照数据源，围绕 `[目标变量名称]` 的预测任务开展验证。验证重点不是单纯观察模型是否能够输出结果，而是考察模型在给定输入条件下对目标变量变化规律的拟合能力、误差控制能力以及在新工况下的泛化表现。

#### （2）数据来源与任务定义

本次验证所使用数据来自 `[公开数据库名称/论文/公开样例来源]`。原始数据包含 `[输入变量1]`、`[输入变量2]`、`[输入变量3]`（如有）以及 `[输出变量]`。根据本项目的数据组织方式，该数据被整理为 `[1D / 2D / 3D]` 预测任务，并按照项目统一目录规范存放于 `[数据目录路径]`。

其中：

- 输入变量为：`[输入变量列表]`
- 输出变量为：`[输出变量列表]`
- 样本总数为：`[N]`
- 数据用途为：`[训练 / 预测 / 外部验证 / 对照分析]`

#### （3）模型与运行条件

本次验证使用 `[current / generic]` 工作流完成，相关模型由程序基于训练阶段自动生成并保存。模型选择依据为 `[RMSE / MAPE / MAE / 综合比较]`，最终采用的模型为 `[模型名称]`。  
本次运行对应的配置文件为 `[配置文件路径]`，模型文件位于 `[模型目录路径]`，结果输出目录为 `[结果目录路径]`。

如需强调可复现性，可补充如下说明：

> 训练与预测过程均保留了配置快照、模型元数据、排行榜和结果文件，因此本次验证结果具备可追溯性与可复现性。

#### （4）验证方法

本次验证采用“数据划分验证 + 指标统计 + 结果对照分析”的方式进行。

1. **数据划分方式**  
   `[说明是交叉验证、留出验证、独立测试集验证，还是直接对公开数据库做外部预测对照]`

2. **验证指标**  
   采用 `[RMSE]`、`[MAE]`、`[MAPE]`、`[R²]` 等指标评价预测精度。其中：
   - `RMSE` 用于反映大误差惩罚后的总体拟合水平；
   - `MAE` 用于反映平均绝对误差；
   - `MAPE` 用于反映相对误差水平；
   - `R²` 用于反映模型对变化趋势的解释能力。

3. **对照方式**  
   将模型预测结果与公开数据库中的参考值进行逐点对照，并结合误差统计表、散点图、曲线图或工况对比图分析预测质量。

4. **验证重点**  
   本次重点关注：
   - 主要工况范围内误差是否稳定；
   - 极值点、拐点附近的拟合是否可靠；
   - 未参与训练的新工况是否出现明显误差放大；
   - 不同评价指标下模型结论是否一致。

#### （5）结果展示

本次预测结果表明，模型在 `[数据集名称]` 上能够较好地重建 `[目标变量]` 的整体变化趋势。对 `[样本数]` 个样本进行统计后，得到：

- `RMSE = [数值]`
- `MAE = [数值]`
- `MAPE = [数值]%`
- `R² = [数值]`

从结果对照可见：

1. 在 `[主要工况区间]` 内，预测值与参考值整体吻合较好；
2. 在 `[特殊区间/边界区间]` 附近，局部误差有所增大；
3. 模型对 `[峰值/谷值/突变段/平台段]` 的刻画基本正确，但在 `[某一局部特征]` 附近仍存在偏差。

#### （6）验证结论

综合误差指标与对照结果可以认为：当前模型对 `[数据集名称]` 的 `[目标变量]` 预测具备 `[较好 / 可接受 / 需要继续优化]` 的精度水平，能够支撑 `[后续分析 / 工程筛选 / 趋势判断 / 辅助设计]`。  
若后续需要进一步提高外部公开数据上的泛化能力，建议从 `[补充训练样本 / 调整分区方式 / 增加特征 / 更换模型]` 等方面继续优化。

## 4. 验证方法写作指南

这一部分是总结报告里最容易写弱、但最重要的部分。建议至少把下面 6 件事写清楚。

### 4.1 写清“验证的对象”

不要只写“对公开数据库进行了预测验证”，而要明确：

- 验证的是哪一个数据集；
- 验证的是哪个目标量；
- 验证的是插值能力、外推能力，还是综合能力。

推荐写法：

> 本次验证针对公开数据库 `[数据集名称]` 中的 `[目标变量]` 展开，重点考察模型在 `[已有工况范围内插值 / 新工况外推]` 条件下的预测精度。

### 4.2 写清“参考真值来自哪里”

如果有真实标签、实验值或公开数据库参考值，一定要交代来源。  
如果只是“无真值的工程预测”，则不能写成“精度验证”，应写成“结果展示”或“趋势分析”。

推荐写法：

> 模型预测值与公开数据库提供的参考值进行逐点对照，参考值来源于 `[论文/公开仓库/标准样例]`。

### 4.3 写清“数据有没有泄漏”

如果验证数据与训练数据存在重叠，报告中应明确说明。  
如果验证数据完全独立，应强调这一点，因为这关系到结论是否可信。

推荐写法：

> 本次用于结果核验的测试样本未参与模型训练，仅用于预测后对照分析，因此能够更真实地反映模型泛化能力。

### 4.4 写清“指标为什么这样选”

建议不要只写一个 `RMSE`。至少要解释为什么这些指标能支撑结论。

推荐写法：

> 本次同时采用 `RMSE` 与 `MAPE` 两类指标，其中 `RMSE` 用于反映绝对误差水平，`MAPE` 用于反映不同量级样本之间的相对误差差异，从而避免单一指标带来的结论偏差。

### 4.5 写清“结果是否属于外推”

对于公开数据库，很多时候最重要的不是“平均误差低不低”，而是“是否预测了未见工况”。  
如果样本超出训练范围，应明确标注为外推测试。

推荐写法：

> 由于本次测试样本中的 `[rpm / wcor / xi / 某输入变量]` 超出了训练样本覆盖范围，因此该结果应视为外推预测结果，需重点关注边界工况下的误差稳定性。

### 4.6 写清“为什么结果可信”

可信性通常来自以下证据：

- 配置文件可追溯；
- 模型元数据完整；
- 排行榜可回看；
- 输出报告、预测结果和图表可复核；
- 验证算例单独归档。

推荐写法：

> 本次验证所对应的输入数据、模型文件、输出结果和误差统计均已归档，可通过配置快照、模型元数据及结果文件进行复核。

---

## 5. 推荐的验证证据清单

在正式总结报告中，建议至少保留以下证据项：

1. **数据来源说明**：公开数据库名称、获取时间、版本或引用文献；
2. **数据范围说明**：样本数、输入输出变量、单位、工况范围；
3. **运行配置说明**：配置文件、模型选择依据、分区方式；
4. **模型说明**：模型名称、训练来源、适用目标量；
5. **误差指标表**：`RMSE`、`MAE`、`MAPE`、`R²`；
6. **结果对照图**：真实值-预测值散点图、关键截面曲线图、误差分布图；
7. **可复核文件**：模型文件、排行榜、报告、预测结果、配置快照；
8. **测试算例归档位置**：建议引用 `data/test_cases` 下的对应目录。

## 6. 简短示例一：current 结构化 3D 算例

以下示例适合写入正文，强调“验证方法”与“证据链”。

### 6.1 示例文本

为验证结构化气动样本上的预测能力，本次选取 `data/current/3d/DATACASE1` 对应算例开展 3D 预测验证。该数据按照 `component/stage/rpm/wcor` 层级组织，目标是预测给定工况下的气动性能量随 `xi` 变化的分布。  
模型训练阶段采用项目标准 3D benchmark 流程完成，并依据排行榜结果选取目标量对应的最优模型；预测阶段使用独立预测目录样本生成结果文件，并与参考值进行逐点对照。

本次验证同时采用 `RMSE`、`MAPE` 和 `R²` 作为评价指标。其中，`RMSE` 用于衡量绝对误差，`MAPE` 用于衡量相对误差，`R²` 用于衡量曲线变化趋势的重建能力。对结果分析时，除了总体误差统计外，还重点检查了不同 `rpm`、不同 `wcor` 条件下的局部预测稳定性，以判断模型是否仅在已见工况内表现良好，还是对邻近新工况也具有可接受的泛化能力。

从验证结果看，模型能够较好跟踪主要工况下目标量的整体变化趋势；在大部分样本范围内，预测曲线与参考曲线保持一致，仅在边界工况和局部陡变区附近出现相对明显偏差。结合误差指标和工况对照结果，可认为当前模型已具备较好的工程辅助预测能力。

### 6.2 示例说明

这个示例的重点不是写出具体数字，而是：

- 写清数据结构和目标；
- 写清训练与预测是两步完成；
- 写清如何核验；
- 写清重点检查的是哪些工况。

## 7. 简短示例二：generic 公开表格数据

以下示例适合写入“公开数据库泛化验证”小节。

### 7.1 示例文本

为评估模型对公开表格数据的适应能力，本次选取 `data/generic/3d` 下的公开样例数据开展预测验证。该数据以表格形式提供 3 个输入变量和 1 个目标输出变量，适合作为通用 3D 回归任务进行独立对照测试。  
训练阶段利用项目通用 3D benchmark 流程完成候选模型评估，并依据 `RMSE` 排序结果选取最优模型；预测阶段对独立样本批量生成预测值，并与公开数据参考值进行对照。

验证过程中，首先检查测试样本是否与训练样本存在重叠；在确认测试数据未直接参与训练后，再使用 `RMSE`、`MAE` 和 `MAPE` 对预测误差进行量化统计。同时，通过真实值-预测值散点图检查是否存在系统性高估或低估，并对高误差样本逐一回查其输入区间是否处于训练样本覆盖边界附近。

结果表明，模型在主要样本区间内具有较稳定的预测能力，但当输入组合接近训练样本稀疏区域时，误差有所增加。这说明当前模型对公开数据库的主体分布具有较好的拟合能力，但对边界工况的外推性能仍有进一步优化空间。

## 8. 报告撰写时常见问题

### 8.1 只有预测结果，没有真值，能不能写成“验证”？

不建议。  
如果没有参考真值、实验值或公开数据库标签，更合适的写法是：

- 结果展示；
- 趋势分析；
- 工况响应分析。

### 8.2 能不能只放最优结果，不写验证过程？

不建议。  
总结报告里最有说服力的不是“最低误差是多少”，而是“这个误差是怎么验证出来的”。

### 8.3 要不要写训练集和测试集是否独立？

建议必须写。  
这一点直接决定读者是否相信结果具有泛化意义。

### 8.4 要不要引用测试算例归档目录？

建议写。  
如果本项目已将测试算例、输出和结果统一归档到 `data/test_cases`，则在报告中引用该目录会明显增强可复核性。
