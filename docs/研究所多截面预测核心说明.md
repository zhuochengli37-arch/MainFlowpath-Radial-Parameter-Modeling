# 研究所 Multi-Section 预测核心说明

## 当前范围

本阶段完成Single/Multi共享的2D和3D径向预测底层。Direct-3D现已增加训练加预测的
单入口和Multi-Section宽表输出；1D预测及旧workline串联仍未改写。共享核心只接收
标准数据对象并返回Canonical结果：

```text
file loader -> PredictionBatch/PredictionSample
            -> radial partition
            -> Model Registry
            -> model selection + metadata validation
            -> 2D/3D input matrix
            -> PredictionResult
```

文件遍历、Legacy路径解析、配置读取及结果写盘属于wrapper层。prediction core不接收
input/output/intermediate folder，也不根据文件名推断物理参数。

## 旧三类流程的实际状态

代码复核确认：

1. Direct 3D：`python -m project1 current direct-3d`依次运行现有3D训练和预测；
   `predict_3d.py`也可单独读取已有模型并输出径向结果。
2. 1D+2D：`workline_pipeline.py`分别运行`predict_1d`、`predict_2d`，随后
   `merge_predictions()`从两个结果目录按相同相对路径和行号合并。1D flow不是2D输入。
3. 1D+3D：没有统一脚本；`predict_1d`先写`results_1d`，用户需把该目录配置成
   `predict_3d.input`，再运行3D预测。

以上文件串联仍作为Legacy Single兼容方式保留。`merge_predictions()`的路径/行号假设
没有进入新的Multi prediction core。

## 标准预测样本与数据优先级

`PredictionSample`至少包含source file、component、stage、station、section、database、
speed、可选flow、xi、Schema身份、原字段来源、源row和section内部row序号。2D允许flow
为空；3D在core入口明确要求flow。

数据优先级为：

1. 已构造标准对象中的Canonical/explicit metadata；
2. 文件内容中的显式字段；
3. Legacy目录metadata；
4. Legacy文件名推断。

后两级只填补缺失值，不覆盖已有值。例如标准对象flow为`0.512`且source filename为
`0.01509.txt`时，3D矩阵使用`0.512`。这也为下一阶段直接把1D预测flow写入内存对象后
调用3D core保留了接口。

Multi文件只通过现有Schema识别、`multi_section_adapter.py`和Canonical数据展开进入
标准样本；2D/3D脚本没有重复解析24/28列。INLET/OUTLET被记录为排除项，不会误当作
`section=None`的MAIN样本。

## 共享partition与输入矩阵

训练和预测共同使用 `model_partitioning.py`：

```text
Single: component + stage
Multi:  component + stage + section
```

section来自数据，可以是RI/RO/SI/SO，也可以是`ROTOR_OUTLET`等其他名称。section仅用于
partition、模型identity、metadata和输出组织，不进入数值矩阵：

```text
2D X = [speed_parameter, xi]
3D X = [speed_parameter, flow_parameter, xi]
```

不同section保持自己的xi顺序和点数，不对齐、不插值、不假设11点。

## Model Registry与选择规则

Multi用户和共享core只接收一个`model_root`。Registry优先读取训练输出中的
`models_manifest.json`，用以下逻辑identity严格过滤：

```text
dimension + component + stage + section + target
```

再结合leaderboard的split/metric选择候选，并从manifest中的path加载模型。target不从
文件名拆分，因此`Total_Pressure_Coefficient`等含下划线名称不会被截断。

模型加载后再次验证metadata中的dimension、component、stage、station、section、
partition、target和inputs；Schema name/version在输入可明确识别时校验。Multi模型缺少
section metadata或section不匹配会拒绝，绝不fallback到Single模型。旧Single模型缺少
新manifest或新metadata字段时可使用leaderboard/旧目录兼容，并发出warning；显式
`partition: all`仍可读取历史`models/all`，但仅限Single wrapper，Multi不允许使用。

targets支持：

- `auto`：按当前partition的Registry记录发现可用targets；
- 显式列表：只预测指定targets；
- 显式target缺失：默认报错，也可显式选择`skip`策略；
- 不同component/section可以拥有不同target集合，不按component硬编码。

## Canonical Prediction Result

每个`PredictionResult`记录source、component、stage、station、section、speed、flow、xi、
target、预测值、partition、模型identity/path和row provenance。结果可以用
`component + stage + operating condition + section + xi`组合，不依赖“两个文件第17行
恰好对应”。row index只用于来源追踪。

旧Single wrapper继续写原格式结果。Direct-3D Multi wrapper按源文件列顺序和相对路径
写回宽表，并同时保留Canonical JSON。各section按真实源行号回填；不等长xi或缺失输出
位置写`NaN`，不会复制源文件中的真实目标值。2D wrapper的最终宽表仍未接入。

## 正式CMP Stage 1 smoke test

2026-09-04使用正式Multi数据库CMP第1级和临时模型目录完成验证：

- 输入880个标准样本；RI/RO/SI/SO各220个、各11个唯一xi；
- targets为`Cpt, Cps, Ctt, Cts, Vz, Rho`；
- 2D选择24个section-aware模型，产生5280条Canonical结果；
- 3D选择24个section-aware模型，产生5280条Canonical结果；
- 每个section/target均产生220条结果；
- 3D的`Cpt` flow-echo探针共880条结果且全部通过，确认矩阵flow来自标准对象；其余
  临时常量模型只用于核对section/target选模与结果数量。

临时模型只验证loader、registry、selection、metadata、矩阵和结果链路，不代表预测精度。
